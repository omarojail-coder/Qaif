# قائف · منصة عرض شحنات LPG

النسخة الحالية تربط توزيع أسطوانات الغاز من غازكو إلى المتاجر بسراج الشحنة المشترك، وتعرض الخريطة، قراءات السراج وتحليلها، هوية الأسطوانة وتاريخ وجودها في أقفاص متعددة، مهام الفحص، وتقرير العميل مع QR وPDF. تستخدم بيانات عرض؛ نموذج 416 الأصلي للأنابيب، وتكييف قراءاته للشحنات لا يمثل نموذج LPG مدربًا أو اعتمادًا ميدانيًا.

**للنشر على الويب:** [دليل GitHub والاستضافة](deploy/README.md). ملف `render.yaml` يجهز عرضًا مجانيًا، وملف `deploy/render-persistent.yaml` خيار مدفوع لحفظ السجلات. [تجهيز Docker](deploy/Dockerfile) يحافظ على الواجهة الحالية ويضيف محرك Linux بالنسخة نفسها.

الأقسام التالية توثق التشغيل المحلي والتقنيات السابقة للأنابيب والدرون التي بني عليها المشروع.

منصة عربية تربط قراءة السرج بالتنبيه، جولة التصوير، مراجعة الصورة، التقرير، والفحص الميداني والقرار. هذه نسخة تشغيل وتطوير؛ ليست إصدارًا معتمدًا لسلامة خطوط الأنابيب.

## تحديث الهوية والخريطة

طُبق الشعار الجديد ولوحة الألوان، وخريطة المترو وتفاصيل الخطوط ونقاط التخطيط كل 31 مترًا، وتبويب أولويات اليوم، وأيقونات القياسات، وخانات RGB والحرارية في السرج والجولة. [تفاصيل التعديلات والتحقق](docs/brand-refresh/README.md).

## تشغيل النسخة الموجودة

افتح `Open-Qaif.cmd` بالنقر المزدوج، ثم اختر «دخول النسخة التجريبية». العنوان المحلي: **http://127.0.0.1:8765**. دخول العرض يمنح دور المدير على الجهاز المحلي فقط. يمكن تجربة الأدوار الأخرى من الإعدادات.

بديل PowerShell:

```powershell
cd C:\Users\omaro\OneDrive\Desktop\projects\Qaif
.\Start-Qaif.ps1
# إيقاف الخادم مع إبقاء البيانات:
.\Stop-Qaif.ps1
```

قاعدة البيانات والملفات في `data/`. يبقى كل تشغيل وتنبيه ومهمة وقرار بعد إعادة التشغيل. احفظ نسخة من هذا المجلد عند أخذ الجهاز إلى الهاكاثون. النسخة تحتوي مهمة وصورة وتقرير اختبار موسومة بوضوح؛ الصورة ليست دليل فحص.

## رحلة التجربة

1. من «المحاكي»، اختر السرج 12 وحالة «تغير ميكانيكي في الانفعال». اختر التشغيل المتدرج لعرض تغير القراءات خلال نحو 18 ثانية، أو الاستيراد الكامل للمراجعة الفورية.
2. افتح «تفاصيل السرج». يظهر تنبيه محسوب من القواعد، والقراءات مقابل ساعات المحاكاة. الحزم المفقودة تظهر فجوات. اطلب التصوير من التنبيه لربطه بنفس التشغيل.
3. في «جولات الدرون»، عيّن المشغّل وحدد الموعد، ثم ابدأ الجولة وارفع صورة فعلية أو صورة مُعدة للعرض. حدد المصدر ونوع RGB/حراري ووقت التصوير إن كان موثقًا.
4. راجع الصورة بشريًا الآن. يصبح زر Gemini متاحًا بعد ضبط المفتاح وإعادة تشغيل الخادم. فشل المزود يُحفظ بوصفه فشلًا؛ لا يحل محله تشخيص مختلق. يمكن عرض صورة من زيارة أخرى لنفس السرج بجانب الحالية.
5. أنشئ مسودة التقرير. افتحه للطباعة/الحفظ PDF، أو حمّل JSON من «التقارير والسجل». اطلب فحصًا مرتبطًا بالتقرير.
6. عيّن المفتش، وسجل الزيارة والنتيجة وقياسات NDT عند توفرها، ثم اكتب قرار الإغلاق. بعد الإغلاق يظهر التقرير بوصفه راجعه المفتش، ويحفظ سجل التغييرات الإجراء وهوية المستخدم.

تتوفر حالات المرجع، البلل، تغير الاقتران، انقطاع الحزم، وثبات الحرارة. إشارة الفيديو الحرارية في صفحة المحاكي **إشارة اختبار يختارها المشغل**، وليست استنتاجًا من المحاكي أو كاميرا حقيقية. تستخدم لتجهيز تسلسل الفيديو فقط، مع حفظ مصدرها في التقرير.

## التقارير السابقة وأولوية التركيب

استورد PDF من «التقارير والسجل». تُستخرج صفحات النص محليًا؛ حدد الصفحة واقتباسًا حرفيًا ووصف الواقعة ثم اعتمدها. الملفات المصورة دون طبقة نص قد تحتاج OCR خارجيًا. عند اعتماد واقعة «إصلاح سابق» تتحدث سابقة السرج، وتدخل في اقتراح أولوية التركيب: لحام +3، تعرض للبلل +2، إصلاح سابق +4. الدرجة ليست احتمال عطل. الاعتماد/الرفض ومبرره يُحفظان. التقرير الجديد يتضمن السوابق المعتمدة واقتباساتها وصفحاتها.

## تحليل الصور والحرارة

ضع المفتاح في ملف `.env` المحلي:

```dotenv
GEMINI_API_KEY=your_private_key
GEMINI_MODEL=gemini-3.8-flash
QAIF_VISUAL_TRANSPORT=antigravity
```

لا ترسل المفتاح في المحادثة ولا تضعه في React. أعد تشغيل الخادم بعد التغيير. الصور تُرسل إلى Google فقط عند اختيار التحليل. النتيجة تفصل المشاهدة عن التفسير وتوصية الفحص. `certainty` تعبير النموذج عن الثقة، وليس احتمال عطل معايرًا. مراجعة جودة النموذج على صور متنوعة ما زالت مطلوبة.

المسار الافتراضي المعتمد هو **Gemini 3.8 Flash عبر Antigravity**، بالإعداد نفسه الذي اختُبر على صور RGB والحرارية. يدعم رفع صورة حالية مع صورة زيارة سابقة اختيارية. يُتابع الموقع الطلب حتى يكتمل، بمهلة 90 ثانية وميزانية 12000 token دون إعادة محاولة توليد تلقائية. طلب التحليل لا يركب ملفات المشروع أو مفاتيحه داخل بيئة الوكيل، ولا يطلب أدوات أو بحثًا خارجيًا.

Antigravity لا يفرض JSON منظّمًا على الخادم؛ لذلك تُطلب الصيغة في التعليمات ثم تُتحقق محليًا، بما فيها إحداثيات الصناديق. فشل التحقق يُسجل بوصفه فشلًا. يُحفظ اسم النموذج ومسار الاتصال ومعرف تنفيذ المزود مع النتيجة، ويظهر «عبر Antigravity» في الواجهة والتقرير. مراجع الاتصال: [Antigravity agent](https://ai.google.dev/gemini-api/docs/antigravity-agent)، و[Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview).

في وضع العرض فقط، يمكن إعادة عرض نتيجة حقيقية محفوظة للصورة والمقارنة والنموذج وعقد التحليل ومسار الاتصال نفسها عند تعذر الخدمة، أو بطلب المشغّل. تظهر بوصفها محفوظة مع وقتها الأصلي؛ لا تُعرض نتائج Gemini المباشرة القديمة على أنها نتائج Antigravity. لا تُستورد نتائج التجارب الخارجية تلقائيًا إلى الموقع. تتضمن الاختبارات استجابات اصطناعية موسومة للتحقق من النجاح، الفشل، المهلة، الإلغاء، وعزل نتائج المسارات. للاختبار أو الرجوع الصريح إلى الاتصال القديم، اضبط QAIF_VISUAL_TRANSPORT=gemini_direct ثم أعد تشغيل الخادم؛ لا يحدث تبديل تلقائي للنموذج أو للمسار.

الألوان الحرارية وحدها لا تنتج Tmax. استورد مصفوفة `NPY` ثنائية الأبعاد بوحدة C أو K، وحدد منطقة الأنبوب بإحداثيات نسبية `[x0,y0,x1,y1]`. يحسب النظام أكبر قيمة والوسيط والفرق داخل المنطقة. البيانات الرقمية مصدرها تصدير المستخدم، ومراجعة الانبعاثية والمعايرة ما زالت مسؤولية البروفة الفعلية. يُمنع تحميل pickle والقيم غير المحدودة.

## الكاميرا عند وصولها

```powershell
.venv\Scripts\python.exe -X utf8 edge\qaif_edge.py --probe
```

الأمر يستعرض الأجهزة المحتملة فقط. لا يثبت دعم SDK أو قراءة درجات حرارة خام. نحتاج اسم الكاميرا، طريقة الاتصال، وصيغة التصدير قبل تنفيذ الالتقاط المباشر. رفع تصديرها كملف يعمل الآن.

توجد أداة رفع ملفات تستخدم مستخدمًا له صلاحية التصوير. اضبط `QAIF_EDGE_USER` و`QAIF_EDGE_PASSWORD` في `.env` ثم:

```powershell
.venv\Scripts\python.exe edge\qaif_edge.py --upload-image path\capture.jpg --mission D-xxxxxxxxxx --mode thermal --source camera_export
```

هذه أداة نقل ملف؛ لا تدعي أنها تلتقط من الكاميرا.

## البناء والتحقق

Python 3.12+ وNode 24. على جهاز جديد: `Setup-Qaif.ps1 -Python python` ثم `Start-Qaif.ps1`. إعداد الحزم يستخدم cache داخل المشروع. مكتبات Python المباشرة مثبتة بإصدارات محددة وnpm يستخدم package-lock.

```powershell
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.venv\Scripts\python.exe -X utf8 -m unittest discover -s backend\tests -v
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run build
Push-Location sim
..\.venv\Scripts\python.exe -X utf8 -m unittest discover -s qaif_saddle_sim\tests -v
Pop-Location
```

خادم FastAPI يخدم React المبني، وSQLite، وملفات الأدلة المحمية، وأحداث WebSocket. الخط العربي والخريطة محليان. خريطة [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/) في المجال العام؛ دليل المواقع تقريبي والمسارات تخطيطية. لا توجد ادعاءات تغطية قياسات للمرافق الـ23 لمجرد ظهورها في الدليل.

نسخة المحاكي 0.4.0 في `sim/` ثابتة. `sim_snapshot_sha256.json` يحفظ بصماتها. بيانات إعادة التشغيل في `fixtures/` تحتوي observed/context/manifest فقط؛ لا يدخل latent أو وصف التدخل إلى قواعد الكشف. المقارنة المرجعية هي تشغيل التحكم المطابق من تجربة محاكاة، وليست توقعًا لنموذج مدرب مستقل. الاستيراد من جهاز دون مرجع يطبق فحوص جودة الحزم فقط.

## إعدادات النشر

راجع [دليل النشر الحالي](deploy/README.md). Docker غير مثبت على الجهاز؛ إعداد GitHub Actions يختبر البناء على Linux بعد رفع المستودع.

- لنوافذ LPG الحالية، أبق `QAIF_DEMO_MODE=true` واضبط `QAIF_PUBLIC_DEPLOYMENT=true` وكلمة مرور خاصة في `QAIF_ADMIN_PASSWORD` قبل أول إنشاء لقاعدة البيانات؛ كلمة المدير الابتدائية لا تتغير لمجرد تعديل env بعد إنشاء المستخدم.
- استخدم HTTPS و`QAIF_SECURE_COOKIE=true`، واضبط الوكيل بحيث يمرر Host وبروتوكول HTTPS وتثق إعدادات uvicorn بعنوان الوكيل المحدد.
- اربط `/data` بتخزين دائم، واختبر النسخ الاحتياطي والاستعادة، وراجع حدود الاستيراد والحمل الفعلي.
- أكمل تقييم التحليل البصري ومعايرة كاشف القراءات وقراءة الكاميرا قبل أي ادعاء اعتماد ميداني.

جهزت إعدادات النشر والاختبارات، ويظل الرفع إلى حساب GitHub وإنشاء خدمة الاستضافة والتحقق من عنوانها العام خطوة مستقلة.
