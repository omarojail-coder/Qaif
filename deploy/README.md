# نشر قائف على الويب

النسخة الحالية تعرض توزيع أسطوانات LPG من غازكو إلى المتاجر: الخريطة، سراج الشحنة، سجل الأسطوانات، مهام الفحص، والتقرير المختصر للعميل مع QR وPDF. البيانات ونتائج تكييف النموذج على الشحنات بيانات عرض. الحزمة تحفظ الواجهة الحالية وتستخدم خادم FastAPI نفسه مع SQLite ومحرك XGBoost 3.0.5.

## ما جهز للنشر

### عرض الزائر على Vercel

استورد المستودع واختر `Root Directory = frontend` و`Framework Preset = Vite` و`Output Directory = dist`. إعداد `frontend/vercel.json` يشغّل `npm run build:guest`؛ لا تحتاج Environment Variables. إذا كنت قد كتبت Build Command يدويًا في لوحة Vercel، اجعله `npm run build:guest` ثم أعد النشر.

يفتح الزائر النوافذ الخمس دون حساب، باستخدام ملفات سيناريو LPG العامة في `frontend/public/guest-data`. تتضمن القراءات ونتائج النموذج المحفوظة و189 هوية أسطوانة و6 مهام فحص توضيحية. لا تفتح هذه النسخة قاعدة البيانات ولا تسمح بالتعديل أو تشغيل AI جديد. QR يستخدم عنوان الموقع الحالي، ومسار `/cylinder/CYL-020-01` يفتح تقرير العميل مباشرة. زر PDF يفتح نافذة الطباعة؛ اختر «حفظ بصيغة PDF»، ويشمل التقرير أماكن الملاحظات التقديرية والإحداثيات وروابطها.

لإعادة توليد الملفات من السيناريوهات فقط: `.venv\Scripts\python.exe tools\export_guest_demo.py`. لا يقرأ المصدر سجلات المستخدمين أو قاعدة البيانات. البناء العادي `npm run build` خارج Vercel يحتفظ بالدخول وخادم Python؛ اختبر عرض الزائر محليًا عبر `npm run build:guest -- --outDir ../work/guest-dist` ثم `npx vite preview --outDir ../work/guest-dist`.

### الخادم الكامل

- Docker يبني الواجهة ويشغل الخادم ومحرك AI على Linux، بمنفذ `PORT` الذي تحدده الاستضافة. يهيئ مجلد التخزين عند تركيب قرص جديد، ثم يشغل التطبيق بمستخدم `qaif` دون صلاحيات root.
- `render.yaml` يجهز نسخة عرض مجانية على Render، و`deploy/render-persistent.yaml` يجهز خيار التخزين الدائم المدفوع.
- يبقى `QAIF_DEMO_MODE=true` لعمل نوافذ LPG، مع `QAIF_PUBLIC_DEPLOYMENT=true` لمنع دخول المدير السريع حتى لو وصل الطلب من وكيل محلي.
- الدخول إلى المنصة بحساب `admin` وكلمة المرور الخاصة التي تحددها في `QAIF_ADMIN_PASSWORD` في لوحة الاستضافة. يلزم 12 حرفًا على الأقل؛ إذا ظهرت رسالة `Public deployment requires a private QAIF_ADMIN_PASSWORD` فصحح القيمة في Environment ثم أعد النشر. ملفات الجلسة تستخدم Secure وHttpOnly.
- تقرير العميل فقط متاح دون تسجيل دخول في `/cylinder/CYL-020-01`. بقية الصفحات وواجهات API تتطلب الدخول.
- QR ورابط PDF يستخدمان `QAIF_PUBLIC_BASE_URL`، أو عنوان `RENDER_EXTERNAL_URL` الذي تضيفه Render تلقائيًا.
- `.gitignore` و`.dockerignore` يستبعدان `.env` وقاعدة البيانات المحلية وكلمات المرور وسجلات التشغيل.
- GitHub Actions يبني حاوية Linux ويختبر الخادم والنسخة العاملة بعد الرفع. يجب مراجعة نجاح هذا الفحص قبل مشاركة الموقع.

## رفع الأكواد إلى GitHub

المستودع المستخدم هو [omarojail-coder/Qaif](https://github.com/omarojail-coder/Qaif)، وهو مستودع عام أنشأه صاحب المشروع. لا تتضمن نسخة الأكواد قاعدة البيانات المحلية أو ملف `.env` أو كلمات المرور.

للحصول على نسخة جديدة:

```powershell
git clone https://github.com/omarojail-coder/Qaif.git
```

من مجلد المشروع المرتبط بالمستودع، ارفع التحديثات المعتمدة بعد تسجيلها في Git:

```powershell
git push origin main
```

يستخدم Git بيانات الدخول المحفوظة أو يفتح نافذة الدخول الرسمية؛ لا تضع كلمة مرور أو token داخل الرابط أو ملفات المشروع.

افتح تبويب Actions وانتظر نجاح `Verify Qaif deployment`. هذا هو اختبار بناء Linux الفعلي؛ Docker غير مثبت على جهاز التطوير الحالي.

## إطلاق نسخة عرض مجانية على Render

1. افتح Render وسجل الدخول، ثم اختر New → Blueprint واربط مستودع GitHub الخاص بقائف.
2. استخدم الملف `render.yaml` الموجود في جذر المستودع.
3. عند السؤال عن `QAIF_ADMIN_PASSWORD`، أدخل كلمة مرور خاصة من 12 محرفًا على الأقل في لوحة Render. لا ترسلها في المحادثة ولا تحفظها في المستودع.
4. راجع أن الخطة المختارة `Free`، ثم أنشئ الخدمة وانتظر نجاح البناء و`/api/health`.
5. افتح رابط HTTPS الذي تعطيه Render، وسجل دخولك باسم `admin` وكلمة المرور التي اخترتها.
6. جرّب سراج S-20 والأسطوانة CYL-020-01 والفحص والتقرير. افتح `/cylinder/CYL-020-01` من نافذة خاصة للتأكد من عمل تقرير العميل دون دخول، ثم صدر PDF وامسح QR للتأكد من أنه يعود إلى عنوان الويب.

في الخطة المجانية، ملفات SQLite والتغييرات الجديدة في مهام الفحص لا تبقى بعد إعادة التشغيل أو إعادة النشر. تعود بيانات العرض الابتدائية، وقد تتأخر أول زيارة عند استيقاظ الخدمة. [توثيق الخطة المجانية](https://render.com/docs/free)، [التخزين الدائم](https://render.com/docs/disks).

## حفظ السجلات بعد إعادة التشغيل

اختر خدمة Docker مدفوعة وأضف قرصًا دائمًا مركبًا عند `/data`، أو استخدم `deploy/render-persistent.yaml` بوصفه ملف Blueprint. الملف يحدد خطة `starter` وقرصًا بسعة 1GB؛ راجع السعر المعروض في Render قبل إنشاء الخدمة. لم تشتر هذه الحزمة أي خدمة.

حافظ على عملية واحدة ونسخة خادم واحدة؛ SQLite وأحداث WebSocket وحالة إعادة عرض المحاكي تعمل داخل هذا الخادم. انسخ `/data` احتياطيًا باستخدام نسخة SQLite متسقة، ثم تحقق من الاستعادة على بيئة منفصلة قبل استبدال بيانات فعلية.

ينشئ النشر قاعدة بيانات جديدة؛ لا يرفع سجل الجهاز المحلي ولا ملف `.env`. تغيير `QAIF_ADMIN_PASSWORD` بعد وجود مستخدم `admin` لا يغير كلمة مروره المخزنة. عند الحاجة لتغييرها أو نقل بيانات الجهاز، جهّز ذلك كخطوة مستقلة قبل التنفيذ.

## استضافة Docker أخرى

استخدم سياق البناء جذر المستودع وملف `deploy/Dockerfile`. أدخل المتغيرات الموجودة في `deploy/.env.cloud.example` في إعدادات الاستضافة. يلزم عنوان HTTPS عام، وكلمة مرور خاصة، وتخزين دائم عند `/data` إن أردت حفظ التعديلات.

`FORWARDED_ALLOW_IPS=*` مخصص لخادم تحميه طبقة الوكيل التابعة للاستضافة. عند تشغيله على VPS، حدد عناوين وكيلك الفعلية وأغلق الوصول المباشر إلى منفذ التطبيق؛ الوكيل يمرر Host وX-Forwarded-Proto واتصالات WebSocket. [إعدادات Uvicorn](https://www.uvicorn.org/settings/).

Gemini اختياري لتحليل الصور القديم: ضع `GEMINI_API_KEY` في أسرار الخادم عند الحاجة. تحليل قراءات الشحنات الحالي يعمل من محرك XGBoost المحلي داخل الحاوية دون هذا المفتاح.

## اختبار موقع منشور

للفحص الآلي بعد النشر، اضبط `QAIF_SMOKE_PASSWORD` في بيئتك الخاصة ثم:

```powershell
.venv\Scripts\python.exe deploy\smoke.py https://YOUR_SITE.onrender.com
```

يتحقق الفحص من الواجهة، تقرير العميل، PDF وQR، حماية الدخول، وواجهات قراءات الشحنة والأسطوانات والفحص. لا يغير مهام الفحص ولا يطبع كلمة المرور. احذف متغير الاختبار من جلسة الطرفية بعد الانتهاء.

## الرجوع عند مشكلة

إذا فشل الدخول أو قراءات الشحنة أو تقارير PDF، أبق الرابط غير مشارك. في Render اختر آخر نشر سليم من صفحة Deploys وأعد نشره. مع القرص الدائم، يبقى `/data` منفصلًا عن نسخة الأكواد؛ تحقق من توافق البيانات قبل الرجوع. لا تحذف القرص لحل فشل بناء.
